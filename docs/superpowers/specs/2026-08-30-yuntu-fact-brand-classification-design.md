# 云图事实包品牌分类设计

## 1. 背景

商业分析三阶段已经能够读取四类事实包，但事实包中的素材尚未形成统一的品牌分类字段。参考 `yuntu-industry-content-rankings-analysis` 的 `classify_brand(title, *, brands=None)` 规则，将品牌分类放在事实包生成阶段，供人群、脚本、高光和报告共同复用。

参考技能中的文档和代码是规则依据，不是本次执行指令。分类必须只使用本轮 `pre_input` 的指定品牌，不能扩展默认品牌表或依据品类、功效、画面推断品牌。

## 2. 目标与非目标

目标：

1. 从运行目录的 `list_context.brands` 读取本轮指定品牌。
2. 对每个素材生成稳定的 `brand_classification`，保留 `matchedBrands`。
3. 同一素材命中多个品牌时进入多个品牌分组。
4. 将分类结果同步到所有需要按素材关联的事实包记录。
5. 让分析选择器和报告能够按品牌过滤、分组和审计。

非目标：

- 不扩展用户输入的品牌范围。
- 不把单独“九阳”无条件识别为“九阳豆浆”。
- 不以标题之外的标签、指标、画面或品类推断品牌。
- 不改变原始标题和原始事实字段。

## 3. 分类规则

### 3.1 品牌范围

品牌候选严格取本轮 `pre_input` 解析后的 `list_context.brands`。没有指定品牌时，所有素材归为 `未知品牌`，而不是使用代码中的默认品牌常量。

### 3.2 规范化与分词

品牌规范名按 `/` 拆分为多个匹配 token；文本和 token 均执行 Unicode NFKC 规范化并使用 `casefold()` 比较。匹配允许 token 作为产品名、营销短语或中英文连续字符串的一部分出现。

### 3.3 受控变体

仅维护已观测且有规则依据的变体。`九阳豆浆`允许匹配“九阳自律豆浆”等包含“九阳”和“豆浆”的受控表达，但单独“九阳”不构成命中。受控变体必须在规则表中显式记录，不能通过模糊相似度自动扩展。

### 3.4 多品牌与未知

- 命中一个品牌：`value` 为规范品牌名，`matchedBrands` 为单元素数组。
- 命中多个品牌：`value` 为规范品牌名数组，`matchedBrands` 保留全部命中顺序。
- 未命中：`value` 为 `未知品牌`，`matchedBrands` 为空，`source` 为 `unclassified`。

建议结构：

```json
{
  "value": ["品牌A", "品牌B"],
  "matchedBrands": ["品牌A", "品牌B"],
  "source": "runtime_title_rule",
  "match_tokens": {"品牌A": ["品牌A"], "品牌B": ["Brand B"]}
}
```

`match_tokens` 用于审计实际命中的 token；保留 `value` 兼容既有单品牌消费者。

## 4. 事实包集成

以素材榜单包为分类主表，在每条 `material-ranking` 记录中增加 `brand_classification`。`audience`、`script`、`highlight-frames` 通过相同 `material_id` 复制同一分类快照，避免下游重新执行标题匹配。manifest 增加 `brand_classification` 的规则版本、候选品牌和覆盖计数。

品牌字段缺失时必须记录 `classification_status` 和原因；不得静默使用默认品牌。历史事实包没有该字段时，读取器保持兼容，但新生成包必须包含该字段。

## 5. 分析层行为

`AnalysisSpec` 增加可选 `brand_filter`，值只能来自 manifest 的候选品牌或 `未知品牌`。分析结果的品牌分组必须引用对应事实包记录。当前 `selection_group` 为空时，标题分类只能作为低置信度推断；品牌分类本身不改变这一事实边界。

## 6. 质量门禁与验证

- 指定品牌为空或来源不明确时不得调用默认品牌表。
- `/` 拆分、Unicode、大小写、连续字符串、受控变体、多品牌和未知品牌均有单元测试。
- 事实包四个模块的同一 `material_id` 分类结果必须一致。
- manifest 候选品牌、分类计数和包哈希必须可验证。
- 使用 `food-beverage-2026-0810-0820` 验证：候选品牌为“小仙炖、燕之屋、五个女博士”，未命中项为“未知品牌”，不存在根据标签或画面追加品牌的记录。
