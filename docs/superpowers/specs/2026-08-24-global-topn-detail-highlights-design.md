# 全局 Top N 素材详情与五指标截帧设计

> **状态：已被 [2026-08-26 高光帧完成态与 Top Values 设计](2026-08-26-highlight-completion-and-top-values-design.md) 替代。** 本文保留为历史设计记录，不得作为当前策略、完成态或交互契约的实现依据。

## 背景

当前第一 RPA 已能根据自然语言转换出的 QuerySpec 拉取并规范化云图行业内容榜素材列表。下一阶段需要在同一次自然语言请求中指定全局 Top N 和五项详情趋势的截帧规则，在列表落盘后仅分析该列表原始排名前 N 条素材。

本期不实现列表结果的自然语言二次筛选、布尔条件树或重新排序。这些能力保留为后续独立迭代。

## 目标

当用户以自然语言请求一个行业内容榜、指定详情分析数量和五项截帧标准时，系统应：

1. 将列表条件与 Top N 解析为 QuerySpec，将截帧条件解析为 HighlightSpec，并在执行前回显两份结构化结果。
2. 调用列表 RPA、落盘并规范化完整的 Top1000 列表。
3. 依据该列表的原始全局 `rank`，只对前 N 条素材调用详情 RPA。
4. 对每个成功持久化的详情，按用户为点赞、流失、点击、互动、评论指数分别指定的策略和数量生成截帧资产。
5. 将选择、详情和截帧的来源、状态与失败原因写入可恢复的批次产物。

## 输入契约

自然语言请求同时表达两组信息：

- 列表筛选条件与全局 `Top N`。
- `include_cover`，以及五项指标各自的截帧 `strategy` 和 `limit`。

解析器输出并校验现有两份配置：

```json
{
  "query": {
    "collection": {
      "target_top_n": 2,
      "candidate_top_n": 1000
    }
  },
  "highlights": {
    "include_cover": true,
    "metrics": {
      "点赞指数": {"strategy": "absolute_max", "limit": 1},
      "流失指数": {"strategy": "local_peaks", "limit": 3},
      "点击指数": {"strategy": "local_peaks", "limit": 5},
      "互动指数": {"strategy": "local_peaks", "limit": 3},
      "评论指数": {"strategy": "absolute_max", "limit": 1}
    }
  }
}
```

`target_top_n` 必须为正整数，且不大于列表采集上限 1000。首期 `candidate_top_n` 固定为 1000，用于保留完整列表产物；它不得扩大详情选择范围。

截帧策略只接受 `local_peaks` 或 `absolute_max`，每项 `limit` 必须为正整数。五项指标均由用户在自然语言请求中明确指定；解析结果必须在 RPA 调用前回显并获得确认。

## 数据流与选择规则

```text
自然语言请求
  -> QuerySpec + HighlightSpec（校验、回显、确认）
  -> 列表 RPA
  -> raw-csv/list.csv + normalized/list-records.json（最多 1000 条）
  -> 全局 rank 升序取前 N 条
  -> 详情 RPA（仅这 N 个 material_id）
  -> 原始详情 + normalized/detail-records/<material_id>.json
  -> 五指标截帧 + highlights-manifest.json
```

- 详情候选按 `normalized/list-records.json` 的 `rank` 升序选择，不根据品牌、触点或 `selection_group` 再次拆分。
- `selection_group` 仅作为详情归属校验上下文透传，不能使 N 变成“每组 N 条”。
- 若列表实际记录数小于 N，则选择全部可用记录，并在批次摘要写入请求数与实际选择数。
- 详情失败不能使用排名较低的候选补位；运行产物必须保留该前 N 素材的失败原因。
- `material_id` 必须是当前成功落盘列表中的数字字符串，不接受外部覆盖。

## 截帧规则与产物

每项趋势独立应用用户指定策略：

- `local_peaks`：按趋势秒级序列选择局部峰值，按值降序、同值按秒点升序排序，取配置的 `limit`。
- `absolute_max`：选择趋势中的全局最大值；同值时取最早秒点。
- 若同一秒点被封面或多个指标选中，只生成一张 JPEG，合并保留全部命中原因。

每个高光帧的清单记录至少包括：素材 ID、相对路径、秒点、帧类型、指标名、策略、指标值、指标内排名，以及是否位于平台返回的高光区间。详情失败、视频下载失败、抽帧失败和规范化失败必须分别记录。

## 边界与错误处理

- 列表 RPA 或列表上下文校验失败时，不得开始详情或截帧。
- 详情响应素材 ID 与请求 ID 不一致、详情格式不合法或归属选择组不一致时，记录该素材详情失败。
- 某项详情趋势缺失或不可解析时，仅该指标不能产出趋势截帧；其它可用指标仍可继续处理，并在高光清单中记录不可用原因。
- 本期不支持对 Top1000 进行列表内二次筛选、AND/OR 条件树、重排序、人工任意点选或按详情趋势筛选。

## 验收标准

1. 自然语言请求可回显为通过现有校验的 QuerySpec 和包含五项指标的 HighlightSpec。
2. 每次成功列表运行均持久化完整 Top1000 列表；详情请求只包含全局 `rank` 前 N 条的 `material_id`。
3. 指定品牌等多选择组场景下，详情总数上限仍为全局 N，不按组扩张。
4. 前 N 中的详情失败被单独记录，系统不得请求第 N+1 条作为补位。
5. 每项配置的指标按其独立策略和帧数选择候选帧；重复秒点只生成一张图片，并保留全部命中原因。
6. 每个详情和截帧产物均可从批次清单回溯至当前列表、素材 ID、解析后的配置和失败分类。

## 后续迭代

后续可在已落盘 Top1000 上增加自然语言二次筛选：将固定列表字段解析为结构化布尔条件树，再在命中集内按用户指定字段重排序并取 Top N。该能力不改变本期全局原始排名 Top N 的选择契约。
